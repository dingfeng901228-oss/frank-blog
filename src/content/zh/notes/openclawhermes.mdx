今天，我终究还是把 **OpenClaw 换成了 Hermes**。

说实话，做出这个决定之前，我其实纠结了挺久。

毕竟 OpenClaw 我已经用了大半年。

这半年里，它帮我做过不少事情，也陪着我折腾过不少项目。博客、网站、代码、服务器、各种自动化任务……很多东西都是在和它一次次磨合的过程中完成的。

所以，如果单纯问我：

**“OpenClaw 好不好？”**

我的答案不会是“不好”。

它确实是一个很有意思的 AI Agent，也让我第一次真正体会到了什么叫做“让 AI 长时间替你干活”。

但问题是——

**我真的不想再折腾了。**

## 又一次升级，又一次出问题

这两天 OpenClaw 发布了新的 `2026.9.1` 版本。这个版本实际上加入了不少改进，包括更新失败后的回滚、Gateway 稳定性优化，以及 Windows 环境下的一些稳定性修复等。

看到新版本的时候，我第一反应其实是：

**要不要升级？**

因为我之前已经升级过好几次 OpenClaw。

而每一次升级，我心里都有点打鼓。

有时候是程序起不来。

有时候是启动以后运行一段时间，Gateway 又莫名其妙退出。

还有一些问题，明明看起来已经解决了，过一段时间又会以另一种方式出现。

所以每次升级之前，我都会有一种很奇怪的感觉：

**到底是在升级软件，还是在给自己增加新的工作？**

但另一方面，最近使用 OpenClaw 的体验确实也让我越来越不满意。

于是我还是决定：

**再给它一次机会。**

结果……

还是熟悉的味道。

升级成功。

启动成功。

运行正常。

然后不到三分钟——

**又退出了。**

我当时甚至有点不知道该说什么。

## 我不想要一个“需要盯着它干活”的 AI

其实，相比程序崩溃，我真正越来越在意的，是另外一个问题。

**执行任务的可靠性。**

我给 AI Agent 分配任务，最希望看到的并不是它马上回复我：

> “好的，我马上处理。”

我真正希望看到的是：

> **你不用管我，我自己把事情做完。**

但在实际使用 OpenClaw 的过程中，我经常会遇到另一种情况。

我交代一个任务。

它回答得非常干脆：

“好的。”

“没问题。”

“我会继续处理。”

然后……

没了。

过了一段时间，我发现事情根本没有继续。

为了避免这种情况，我甚至要求它：

**每隔半小时主动汇报一次进度。**

但现实依然是：

我不主动问，它有时候就不主动汇报。

等我去问：

> “现在做到哪里了？”

它才突然：

> “抱歉，刚才没有及时汇报……”

然后继续干活。

这种感觉特别像办公室里的一种同事：

**你盯着他，他就认真工作；你不盯着，他就不知道跑到哪里去了。**

当然，这个比喻有点损。

但作为一个长期使用 AI Agent 的人，我越来越觉得：

**Agent 最重要的能力之一，就是让人放心。**

## 然后，我开始尝试 Hermes

既然 OpenClaw 又出了问题。

那就干脆换一个试试。

于是我开始用了 **Hermes**。

结果让我有点意外。

因为 Hermes 给我的第一感觉就是：

**它好像真的比较愿意把事情做完。**

我交代一个任务之后，它不会因为中间遇到一个小问题就直接停在那里等我。

而是会继续尝试。

遇到问题，就分析问题。

需要修改代码，就修改。

需要重新执行，就重新执行。

而且过程中会告诉我：

现在做到哪里了。

遇到了什么问题。

接下来准备怎么处理。

这种体验其实非常重要。

因为我真正需要的不是一个：

**“会回答问题的 AI。”**

而是一个：

**“可以把任务交出去的 AI。”**

## 最明显的区别：GitHub CI

让我感受最明显的，是 GitHub。

以前使用 OpenClaw 的时候，经常是这样的流程：

```
我：
把这个功能做好，然后提交 GitHub。

OpenClaw：
好的。

↓

代码修改完成

↓

git push

↓

任务结束
```

但实际上，真正的问题可能才刚刚开始。

因为 push 完之后：

**CI 到底过没过？**

它未必会继续关注。

于是最后还是我自己去看 GitHub。

发现：

```
❌ Build failed
```

然后我再把错误信息复制给它：

> “这里失败了，你看看。”

它才继续：

```
分析错误
↓
修改代码
↓
git push
↓
我再检查
```

整个过程，我始终需要站在旁边盯着。

---

而 Hermes 给我的体验更像是：

```
修改代码
↓
git commit
↓
git push
↓
等待 CI
↓
检查结果
↓
失败？
   ↓
分析原因
↓
修改代码
↓
重新 push
↓
再次检查
↓
直到通过
```

**整个过程我甚至不需要插手。**

这其实就是我理解的 Agent 和普通 AI 助手之间最大的区别。

普通 AI 是：

> “告诉我下一步该怎么做。”

而真正让我觉得有价值的 Agent 应该是：

> **“把目标告诉我，剩下的事情我自己完成。”**

## 我终于明白，我真正需要的是什么

用了 OpenClaw 大半年之后，我其实越来越清楚自己真正需要的并不是一个“最强”的 AI。

我需要的是一个：

**可靠的 AI。**

我不在乎它是不是每次都能给出最漂亮的回答。

也不在乎它是不是每一次都能一次性解决问题。

我更在乎的是：

- 能不能持续执行任务？
- 遇到问题会不会自己处理？
- 能不能主动汇报进度？
- 能不能记住上下文？
- 能不能把一个任务真正做到结束？
- 能不能在我不盯着它的时候，依然继续工作？

因为对我来说，AI Agent 的价值，从来不是帮我节省几分钟。

而是：

**让我可以同时做更多事情。**

如果一个 Agent 每做一件事情，我都需要站在旁边监督，那它实际上并没有真正替我承担多少工作。

只是把“打字”这部分工作交给了 AI。

而我自己变成了：

**AI 的项目经理。**

## 我并不是否定 OpenClaw

所以，这篇文章并不是为了踩 OpenClaw。

恰恰相反。

我是真的感谢它。

如果没有 OpenClaw，我可能不会这么早开始真正使用 AI Agent。

更不会花这么多时间去研究：

- Agent
- Memory
- Skills
- Automation
- Tool Calling
- MCP
- Long-running Tasks

这些东西。

OpenClaw 让我第一次意识到：

**AI 不一定只是一个聊天机器人。**

它完全可以成为一个长期运行的数字助手。

而 Hermes 只是让我觉得：

**也许现在到了换一个工具的时候。**

事实上，Hermes 官方本身就提供了 OpenClaw migration，可以迁移包括设置、记忆、skills 等在内的一部分用户数据，所以这次转换并不是完全从零开始。

## 软件没有永远的忠诚

其实软件和人一样。

没有必要因为你曾经用了很久，就必须一直使用下去。

以前觉得好用。

现在觉得不好用。

那就换。

以前适合自己的东西。

现在不适合自己。

那就换。

这和背叛没有关系。

只是：

**需求变了。**

我从最开始接触 AI Agent，到现在已经过去了一段时间。

我的需求也发生了变化。

以前我觉得：

> “能帮我执行命令就不错了。”

后来我开始希望：

> “能不能自己完成一个完整任务？”

再后来，我开始希望：

> “能不能不用我盯着？”

现在我最在意的是：

> **“我把事情交给你之后，能不能放心地去做自己的事情？”**

这可能才是我现在对 AI Agent 最大的期待。

## 再见，OpenClaw

所以今天，我终于做了这个决定：

**OpenClaw，我是真的不想再折腾了。**

用了大半年。

有过折腾。

有过崩溃。

有过升级失败。

也有过很多让我觉得：

**“这东西真挺好用。”**

的时刻。

所以，我不会说：

**“OpenClaw 再见，垃圾软件。”**

我更愿意说：

**谢谢你陪我走过这一段。**

只是接下来，我想换一条路。

换一个 Agent。

换一种使用方式。

也许 Hermes 最终也会让我失望。

也许过几个月，我又会因为某些原因换回 OpenClaw。

谁知道呢？

毕竟 AI Agent 这个领域变化得太快了。

今天的“最好用”，可能几个月之后就已经是另一回事。

但至少现在：

**我想把任务交给 Hermes，然后去做我自己的事情。**

至于它能不能证明自己——

**让时间来回答吧。**
